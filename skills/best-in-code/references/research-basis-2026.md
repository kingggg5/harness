# 2026 Research Basis

Read this reference only when evaluating or changing the Harness itself. It is dated evidence, not a permanent claim about every model or task.

Background notes on Jev, async operations, performance sources and framework comparisons: docs/RESEARCH_NOTES.md in the repository.

## Findings that shape this Harness

- Harness quality is a model–harness–environment property. A useful evaluation records task specification, context selection, tools, memory, state, observability, failure attribution, verification, permissions, entropy, and human intervention—not only whether a final patch passes. Source: [AI Harness Engineering: A Runtime Substrate for Foundation-Model Software Agents](https://arxiv.org/abs/2605.13357), 2026-05-13.
- Structured artifact handoffs, explicit completion contracts, and an evaluator separated from the generator improved long-running full-stack work in Anthropic's reported experiments. The evaluator still needed calibration, and additional loops increased cost and sometimes complexity, so Harness activates expensive evaluation only where risk or difficulty justifies it. Source: [Harness design for long-running application development](https://www.anthropic.com/engineering/harness-design-long-running-apps), 2026-03-24.
- The same Anthropic work found that scaffolding assumptions can go stale as models improve: context resets and per-sprint evaluation that helped an older model became avoidable overhead for stronger models on easier tasks. Harness therefore changes one component at a time and keeps a planner, evaluator, reset, loop, or agent only when representative evals show lift.
- Anthropic's managed-agent architecture separates durable session events, the harness control plane, and sandbox compute behind stable interfaces so each can recover independently, with credentials outside the sandbox. Harness mirrors that boundary with an append-only receipt ledger that never launches workers, interprets verifier IDs, or owns secrets. Source: [Scaling Managed Agents: Decoupling the brain from the hands](https://www.anthropic.com/engineering/managed-agents), 2026-04-08, last verified 2026-10-26.
- OpenAI's long-running (`/goal`) and scheduled-task guidance keeps outcomes, constraints, verification, steering, and permissions explicit while placing schedules, local-machine availability, and isolated worktrees in the host, and advises reviewing early scheduled runs before relying on a cadence. Harness therefore keeps `LOOP-CONTRACT.json` portable and treats scheduling, metering, process control, and worktree creation as external capabilities rather than prompt claims. Sources: [Long-running work](https://learn.chatgpt.com/docs/long-running-work), [Scheduled tasks](https://learn.chatgpt.com/docs/automations), last verified 2026-08-25.
- SkillsBench evaluated 7,308 trajectories over 84 tasks: curated skills improved average pass rate by 16.2 percentage points, but software-engineering gain was 4.5 points, 16 tasks regressed, self-generated skills had no average benefit, and focused 2–3-module skills beat comprehensive documentation. Harness keeps skills curated, conditional, focused, and subject to A/B removal rather than treating more instructions as automatically better. Source: [SkillsBench](https://arxiv.org/abs/2602.12670), 2026-02-13.
- Agent eval trials need clean isolated environments because leftover files, caches, shared resource exhaustion, or prior Git history can correlate failures or leak answers. Evaluate the final environment outcome separately from policy/trajectory quality, and inspect traces before trusting aggregate scores. Source: [Anthropic, Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents), 2026-01-09.
- Worktree isolation is useful for version-control ownership but not a security sandbox. OpenAI's 2026 Agents SDK separates harness orchestration from sandboxed compute so credentials can stay outside model-generated execution. Harness likewise treats filesystem/process/network sandboxing, credentials, and worktree separation as distinct capabilities. Source: [The next evolution of the Agents SDK](https://openai.com/index/the-next-evolution-of-the-agents-sdk/), 2026-04-15.
- OpenAI's Symphony uses a task board as a control plane, maps active work to dedicated workspaces, and schedules unblocked DAG tasks. OpenAI describes it as an intentionally minimal reference implementation rather than a maintained standalone product, so Harness adopts durable task identity and central supervision only after session-management overhead is measured; it does not add Symphony or a ticket system as a dependency. Source: [An open-source spec for Codex orchestration: Symphony](https://openai.com/index/open-source-codex-orchestration-symphony/), 2026-04-27.
- Current harness comparisons hold the model, task, context window, reasoning effort, tool selection, and MCP access fixed and evaluate task resolution together with token efficiency. Source: [GitHub Copilot agentic harness evaluation](https://github.blog/ai-and-ml/github-copilot/evaluating-performance-and-efficiency-of-the-github-copilot-agentic-harness-across-models-and-tasks/), 2026-06-25.
- Harness's own A/B (2026-10-19, Sonnet subagents, mock host skills, fixture repositories): loading Harness on routine bug fixes, small features and UI work added about 20–30% tool calls and about 10% estimated cost without changing outcomes, and strong models caught duplicated logic, hidden callers, unsafe file names and red-test traps unaided. Explicit reviews with Harness loaded the matching security skill 3/3 against 1/3 without. The skill description therefore targets reviews, specs, test-first and risky or cross-module work, and finish-checklist or step-batching rules that only added turns were not adopted.
- Harness's own follow-up (2026-10-26, Haiku subagents): a routine-task skip clause in a skill description can override an explicit `Harness:` invocation (0/3 loads) unless the description states that explicit invocation always loads (6/6). Project decisions that cannot be inferred from code were followed 3/3 when the AGENTS.md block or a session-start digest surfaced them, but only 2/3 under a block that told agents to skip Harness for small features; the digest needed the fewest tool calls.
- Instructions alone do not make agents use a tool. In Marginlab's Terminal-Bench 2.0 run, Codex with GPT-5.4 called Context7 in only 6 of 89 tasks despite an `AGENTS.md` instruction to use it, and pass rate moved from 70.8% to 71.9%, within noise. Harness therefore makes reference and skill selection an explicit route line and phase-boundary match rather than a passive suggestion, and treats a documentation backend as evidence support, not a quality multiplier. Source: [Do MCPs improve coding agents? Part 1](https://marginlab.ai/blog/do-mcps-improve-coding-agents-part-1/), 2026-04-10, last verified 2026-10-19.
- Documentation backends are an injection surface too: CVE-2026-75130 covers Context7 through 2.1.2, where content planted in custom AI instructions was served to coding agents during routine documentation requests. Harness treats every documentation result, including library-owner rules, as untrusted retrieved data. Source: [VulnCheck advisory](https://www.vulncheck.com/advisories/context7-prompt-injection-via-custom-ai-instructions), 2026-08-18, last verified 2026-10-19.
- Third-party context files are a semantic supply-chain surface. Cloud Security Alliance cites a February 2026 audit finding security flaws in 1,467 of 3,984 sampled skills and recommends provenance, integrity, inventory, and behavior monitoring. Source: [Agent Context Poisoning: SKILL.md and the New AI Supply Chain Attack Surface](https://labs.cloudsecurityalliance.org/research/csa-research-note-skill-md-agent-context-poisoning-20260506/), 2026-05-06.
- Caveman's own measurement notes say the skill compresses output only, adds input context, and can be net-negative on already terse workloads. Therefore it remains opt-in and must be tested with provider-billed totals and task-quality gates. Source: [Caveman Honest Numbers](https://github.com/JuliusBrussee/caveman/blob/main/docs/HONEST-NUMBERS.md), last verified 2026-08-22.
- UX heuristics are broad rules of thumb rather than specific compliance requirements, so Harness records each law as a falsifiable design rationale and separates heuristic review from representative-user evidence. Source: [Nielsen Norman Group: 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/), last verified 2026-08-22.
- WCAG 2.2 provides testable accessibility success criteria and W3C advises using the current version for future applicability. Harness targets WCAG 2.2 AA unless a stricter project standard is approved, but requires a declared test scope before claiming conformance. Source: [WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/), last verified 2026-08-22.
- WCAG 2.2 Target Size (Minimum) sets a 24×24 CSS-pixel floor with exceptions, so Harness treats it as a floor and prefers larger touch targets. Source: [Understanding Target Size (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum).
- Pinterest's official copyright guidance says permission may need to come from the copyright holder and Pinterest may not know who owns a Pin. Harness therefore uses Pinterest as read-only inspiration, follows outbound links to original sources, and defaults reuse status to not cleared. Source: [Pinterest Help: Copyright](https://help.pinterest.com/en/article/copyright), last verified 2026-08-22.
- Pinterest documents its visual search features; Harness uses public read-only search or domain-filtered image search instead of uploading project material. Source: [Pinterest Help: Visual search features](https://help.pinterest.com/en/article/use-visual-search-features).
- `AGENTS.md` is an open, plain-Markdown instruction format supported by multiple coding agents, and Codex resolves hierarchical instruction files with nearer project files taking precedence. Harness therefore uses a concise project `AGENTS.md` as its provider-neutral entry point rather than copying the whole workflow into vendor files. Sources: [AGENTS.md open format](https://agents.md/), [Codex AGENTS.md guidance](https://learn.chatgpt.com/docs/agent-configuration/agents-md), last verified 2026-08-22.
- Claude Code supports importing `AGENTS.md` from `CLAUDE.md`, while Gemini CLI supports `@file` imports from `GEMINI.md`. Harness uses thin import adapters so the providers share one canonical instruction source. Sources: [Claude Code memory](https://code.claude.com/docs/en/memory), [Gemini CLI context files](https://github.com/google-gemini/gemini-cli/blob/main/docs/cli/gemini-md.md), last verified 2026-08-22.
- Codex local memories are helpful recall rather than the right place for required team rules, and local memories can be disabled. Harness therefore keeps durable cross-model facts and preferences in explicit project files and treats provider memory as a hint. Source: [Codex memories](https://learn.chatgpt.com/docs/customization/memories), last verified 2026-08-22.
- Claude Code plugins and Gemini CLI extensions both discover Agent Skills from a shared `skills/` tree but use different package manifests. Harness ships one skill implementation with thin provider-specific manifests. Sources: [Claude Code plugin reference](https://code.claude.com/docs/en/plugins-reference), [Gemini CLI extension reference](https://geminicli.com/docs/extensions/reference/), last verified 2026-08-22.

## Best default architecture for 2026

1. Start with one capable owner, the smallest verified toolset, and deterministic checks.
2. Add a requirement/plan artifact when ambiguity can cascade; avoid specifying low-level implementation prematurely.
3. Add graph fan-out only for independent jobs. Use one coordinator, exact artifacts, and one integration owner.
4. Give each concurrent writer a clean workspace from the same exact revision; separately sandbox processes/network/credentials and allocate mutable services.
5. Add evaluator/repair loops only with a measurable rubric and hard transition/time/token/cost/failure stops.
6. Use structured handoffs or context reset only when long-run coherence evidence requires them; otherwise prefer lower overhead.
7. Add an always-on coordinator or task-board control plane only when measured human session-switching is the bottleneck.
8. Evaluate accepted outcome, trajectory/policy compliance, latency, tokens/cost, human interventions, unrelated diff, and recovery across repeated isolated trials. Remove one Harness component at a time when it no longer earns its cost.

## Evaluation protocol

For an A/B comparison, hold the task, repository revision, model, reasoning effort, permissions, tools, initial context, and acceptance criteria constant. Record provider-billed input/output/cached/reasoning tokens when available, cost, elapsed time, human interventions, defect loops, requirement-level checks, unrelated diff, security incidents, and final acceptance. Repeat across representative easy, medium, and hard tasks; do not generalize from one run.

Change one Harness component at a time. Compare the full route with the component removed and with the simplest single-owner baseline. Keep a component only when it improves accepted outcomes, evidence quality, or total cost/latency for the target task distribution without unacceptable regressions.

## Module evidence

### Graph Engineering

Supports [graph-engineering.md](graph-engineering.md), checked August 2026.

The Graph Engineering design is an evidence-informed synthesis, not a claim that one framework or graph fits every task:

- [Google Research, “Towards a science of scaling agent systems” (January 28, 2026)](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/) evaluated 180 configurations. Central coordination improved a parallelizable task by 80.9%, while every tested multi-agent architecture degraded sequential planning by 39–70%; independent agents amplified errors more than a centralized coordinator. This supports conditional fan-out and one merge owner.
- [Anthropic, “Building effective agents”](https://www.anthropic.com/engineering/building-effective-agents) recommends starting with the simplest composable workflow, using parallelization for independent subtasks, orchestrator-workers for unpredictable decomposition, and evaluator-optimizer only when criteria are clear and iteration measurably helps.
- [Anthropic, “Effective context engineering for AI agents”](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents) treats context as finite and favors the smallest high-signal set, just-in-time retrieval, compaction, structured note-taking, and subagents with focused context.
- [OpenAI, “A practical guide to building agents”](https://openai.com/business/guides-and-resources/a-practical-guide-to-building-ai-agents/) describes manager and decentralized handoff patterns, while noting that dynamic code-first orchestration can be preferable to a fully declarative graph. Harness therefore validates a portable contract without forcing one runtime.
- [Karpathy's LLM Wiki prototype (April 4, 2026)](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) keeps raw sources immutable, treats the linked wiki as an LLM-generated layer, and begins with an index and append-only log before adding heavier search. Harness applies the authority separation without adding another generic knowledge file.
- [Graph Engineering repository](https://github.com/codejunkie99/graph-engineering) and [Greg Isenberg's “Why Graph Engineering will 10x your Claude/Codex” video](https://www.youtube.com/watch?v=JWhICz1QR8M) are useful community explanations of jobs, arrows, shared state, diamonds, gates, and oversized-graph risk. Treat “10x” as a title, not benchmark evidence; primary measurements above control Harness policy.
- [Karpathy AI Engineering Playbook summary](https://www.aibuilderclub.com/blog/karpathy-ai-engineering-playbook) was used as a lead for spec/diff/eval and compiled-knowledge ideas.

### Execution isolation

Supports [execution-isolation.md](execution-isolation.md), checked August 2026.

- [Git's current worktree documentation](https://git-scm.com/docs/git-worktree) confirms that linked worktrees have separate `HEAD`/index state while sharing repository administration and refs, and that normal removal refuses dirty worktrees. That supports worktree isolation plus separate resource and cleanup checks.
- [Kun Chen's “L8 Principal's Agentic Engineering Workflow”](https://www.youtube.com/watch?v=iQyg-KypKAA) demonstrates minimal global/project memory, progressive skills, visual planning, isolated validation, worktree parallelism, long-running loops, and a central “first mate.” Productivity numbers in the video are self-reported, not Harness benchmarks; Harness adopts only the bounded contracts in [execution-isolation.md](execution-isolation.md).
- The creator's primary repositories document the concrete patterns: [Treehouse](https://github.com/kunchenguid/treehouse) for leased worktrees, [GNHF](https://github.com/kunchenguid/gnhf) for commit/rollback iteration with runtime caps, [No Mistakes](https://github.com/kunchenguid/no-mistakes) for an isolated validation gate, and [Firstmate](https://github.com/kunchenguid/firstmate) for centralized supervision. Harness does not inherit their installation commands or standing permissions.

### Loop Engineering

Supports [loop-engineering.md](loop-engineering.md), checked August 2026. It also rests on the OpenAI long-running and scheduled-task, Anthropic harness design, and Managed Agents findings above.

- [OpenAI eval-driven improvement loop](https://learn.chatgpt.com/use-cases/iterate-on-difficult-problems) recommends deterministic plus optional judge scores, machine-readable artifacts, explicit thresholds, and a running iteration log.
- [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model) confirms Sol/Terra/Luna routing and beta multi-agent support, while recommending multi-agent only for cleanly independent workstreams and measured model/effort selection.
